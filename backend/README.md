# Portfolio Backend — PayloadCMS 3

Headless CMS backend for the portfolio. Serves a **public REST API** consumed by
the static `../frontend`. Payload 3 (Next.js) + SQLite (dev) + Lexical rich text.

See [`../docs/sprint-2/plan.md`](../docs/sprint-2/plan.md) for the full design.

## Run (first time)

```bash
cd backend
npm install                 # installs Payload + Next + React (one-time, heavy)
npm run dev                 # starts Next.js on http://localhost:3000
```

- **Admin panel:** http://localhost:3000/admin → create the first admin user on
  first visit (Payload prompts for email/password).
- **REST API base:** http://localhost:3000/api
  - `GET /api/documents?depth=1`
  - `GET /api/document-categories?sort=order`
- **GraphQL:** http://localhost:3000/api/graphql (and `/api/graphql-playground` in dev)

> SQLite file (`payload.db`) is created automatically on first run — zero infra.
> Regenerate TypeScript types after schema changes: `npm run generate:types`.

## Verify the frontend can reach it

In another terminal:
```bash
cd frontend && python3 -m http.server 8080
```
Then `curl http://localhost:3000/api/document-categories` should return JSON
(`{ docs: [...] }`). CORS is pre-allowed for `localhost:8080` (see `.env`).

## Collections (so far — Phase 0 + start of Phase 1)

| Collection | Purpose | Public read |
|---|---|---|
| `users` | admin login (`auth`) | no |
| `document-categories` | ordered groups (Pinned/Research/Other) — the **categories grouping** | yes |
| `documents` | downloadable files (`upload` → filesize/mimeType auto); FK → category | yes |

Phases 1–4 add: `articles` + `tags`, `projects` + `technologies`,
`social-profiles`, and the `site-config` / `home` / `nav` globals. See
[`../docs/sprint-2/tasks.md`](../docs/sprint-2/tasks.md).

## Structure

```
backend/
├── payload.config.ts          # buildConfig: sqlite, lexical, cors, secret, collections
├── next.config.mjs            # withPayload()
├── tsconfig.json              # @payload-config path alias
├── .env                       # PAYLOAD_SECRET, DATABASE_URL, CORS origins
└── src/
    ├── collections/           # Users, DocumentCategories, Documents (+ more per phase)
    ├── payload-types.ts       # auto-generated (npm run generate:types)
    └── app/(payload)/         # admin + REST route group (generated boilerplate)
```

## Notes

- The `src/app/(payload)/` files are Payload's generated boilerplate (fetched
  from context7, July 2026). Only `importMap.js` is auto-regenerated by Payload;
  the rest are safe to leave as-is. If Payload ever rewrites them on a future
  upgrade, that's expected.
- `package.json` uses `latest` for the Payload cluster so all `@payloadcms/*`
  packages resolve to the same (in-sync) version. After a successful `npm
  install`, consider pinning via a `package-lock.json` for reproducibility.
- If `npm install` reports a Payload version-sync error, the supported fallback
  is the official scaffolder: `npx create-payload-app@latest` (SQLite, blank),
  then drop the collections from `src/collections/` + `payload.config.ts` in.
